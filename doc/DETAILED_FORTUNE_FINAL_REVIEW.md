# 상세 운세·월운 종합 검증

검증일: 2026-10-16. 실행순서 13단계 완료 기록. Node 24.13.1, Windows Chrome의 격리된 임시 프로필에서 검증했다. 운영 배포는 수행하지 않았다.

## 결과

- 전체 모듈 테스트 **63개 통과, 실패 0개**. 12단계의 60개에 종합 검사 3개를 추가했다.
- 기존 네 메뉴 브라우저 회귀 및 상세 운세 브라우저 검사 모두 통과했다. 실제 화면에서 2026년 12절입 각각의 전·정각·후 갱신도 추가 확인했다.
- 독립 월 경계 시각 **36건 모두 허용 차이 60초 이내**, 최대 절댓값 차이 **28초**. 2024·2026년 기존 표본 24건에 2025년 신규 12건을 추가한 결과다.
- 1901~2050년 150개 연도·1,800개월의 연속성과 계산→해석 연결을 확인했다. 이는 엔진 내부 생성·연결 검사이며 전 기간 시각 정확성의 독립 보증이 아니다.
- 이번 검사에서 앱 계산·콘텐츠·화면의 수정이 필요한 결함은 발견하지 않았다. 테스트와 문서 보강만 수행했다. 문서의 오래된 Node 실행 옵션과 현황 안내, 실행순서 문서 끝의 빈 줄을 정리했다.

## 1. 독립 시각 자료와 정밀도

출처는 한국천문연구원의 [2024 달력자료](https://astro.kasi.re.kr/kor/life/post/calendarData?search_year=2024), [2025 달력자료](https://astro.kasi.re.kr/kor/life/post/calendarData?search_year=2025), [2026 달력자료](https://astro.kasi.re.kr/kor/life/post/calendarData?search_year=2026)다. 2025·2026 페이지는 이번 작업에서 다시 열어 확인했다. 페이지는 공식 월력요항 발표 전 참고자료라고 명시한다. 2025 자료 생성 표기는 V1.0a, 2024-05-07 14:23이다.

- 각 연도의 소한·입춘·경칩·청명·입하·망종·소서·입추·백로·한로·입동·대설 12건을 비교했다. 중기는 월 경계 표본에 포함하지 않았다.
- 원자료는 한국 시간의 **분 단위**다. 비교를 위해 초를 00으로 두었으며, 초 단위 확정 관측값이라고 간주하지 않는다.
- 허용 절댓값 차이는 기존 정책대로 **60초**다. 엔진의 UTC 순간을 같은 순간의 한국 표준시와 비교한다. 차이는 `엔진 - 참고 시각`의 초 수다.
- 2024·2026 fixture는 기존 전사 자료를 재사용한다. 2025의 신규 전사 자료는 `tests/fixtures/kasi-monthly-2025.mjs`에 출처·정밀도·작성일과 함께 보관했다.
- 모든 36건의 참고 시각·엔진 시각·부호 있는 차이는 [MONTHLY_TERMS_RESULTS.json](./MONTHLY_TERMS_RESULTS.json)에 보관했다. `tests/fortune-final.test.mjs`에서 재계산한다.

기존 HKO 336건은 날짜 단위 대조이고, USNO 60건은 분점·지점 표본이다. 이들을 월 경계 12절입 시각의 전수 대조로 합산하지 않았다. 이번 36건 역시 1901~2050년 모든 월 경계 시각의 독립 전수 대조가 아니다. 표본에서 통과한 60초 허용치를 전체 역사 기간의 오차 상한으로 주장하지 않는다.

경계에서 계산 구간은 시작 포함·끝 제외다. ±60초에는 `activeSegmentId=null`, 양쪽 후보를 반환한다. 범위 밖 순간은 현재 강조를 만들지 않는다. 기존 검사에서 윤년 2월 29일, 양력 월 시작, 한국 날짜로 넘어가는 2024 대설, 2050년 말과 내부 계산용 2051 소한·입춘을 확인했다.

## 3. 콘텐츠 편집 검수

[대표 출력 3건](./DETAILED_FORTUNE_SAMPLES.md)의 총론·네 분야·월운 전체를 다시 읽고, 연간/월간 연결문구 100개를 확인했다.

| 조합 | 확인한 일관성 |
| --- | --- |
| 정재 / 편재 | 반복 예산 관리와 새 제안 검토를 연결하되, 예산 범위·유지 비용을 먼저 확인한다. 무조건 확장/지출하라는 지시가 없다. |
| 편관 / 정인 | 도전의 책임을 혼자 떠안게 하지 않고 지원·질문·회복 시간을 함께 다룬다. 위험·질병을 예고하지 않는다. |
| 상관 / 정관 | 방법 개선과 지킬 약속을 구분한다. 모든 규칙을 깨거나 무조건 따르라는 상반된 명령 대신 변경 범위와 완료 기준을 확인한다. |

자동 검사는 연간 A·월간 M과 연결문구 조건이 서로 어긋나는지, 월간 행동이 다른 유형의 것으로 섞이는지, 필수 분야/본문 누락, 정확히 같은 문단/연결문장 중복, 금지된 확정 표현을 확인한다. 의미상 상충 전체를 자동으로 판정한다는 뜻은 아니다. 의미 검수는 위 표본과 연결문구 읽기로 보완했다.

연간 본문 100문단과 연결문구 100개는 각각 완전 동일 문자열 중복이 없다. 동일한 M 및 A/M이 다시 적용되거나 같은 절기 월이 양력 월을 넘어가면 문구가 반복되는 것은 설계된 동작이다. ‘살펴보세요/확인해 보세요’ 같은 말투의 유사성은 남아 있으며 무한한 개인화나 전문가 감수 완료로 표현하지 않는다.

## 4. 실제 화면 검수

- 사주팔자의 상세 링크, 세운 요약 카드의 상세 버튼, 연도·세운·월 선택, 5개 분야와 12개월 목록을 확인했다.
- 세운 선택을 바꿔도 월운의 실제 A/M 연결은 유지된다. 출생 전 월 안내, 출생일 잘라내기, 부분 사주, 2050 상한을 확인했다.
- 입력 수정으로 선택 연도가 무효가 되는 경우, 메뉴 복귀·새로고침 복원, 손상된 저장값, 저장 차단, 범위 밖 현재 연도, 계산 실패를 확인했다.
- 2026년 12절입 각각 -61초·정각·+61초에서 현재 구간 1개 → 경계 후보 2개 → 현재 구간 1개로 갱신되는지 확인했다. 입춘 자동 세운 선택 유예, 새해의 연도 변경과 이전 세운 적용, 수동 선택 유지, 경계 갱신 중 버튼 포커스 보존도 확인했다.
- 네이티브 월 버튼의 Enter 조작과 포커스를 실제 Chrome 입력 이벤트로 검수했다. 320·360·768·1280px에서 가로 넘침 검사를 통과했다.
- 최신 [320px 상세](../tests/screenshots/detailed/detail-320.png), [320px 월운](../tests/screenshots/detailed/monthly-320.png), [1280px 월운](../tests/screenshots/detailed/monthly-1280.png)을 열어 줄바꿈·선택 강조·기간 안내를 확인했다. 실제 모바일 하드웨어·모든 브라우저/스크린리더 조합을 검수한 것은 아니다.

## 재현

프로젝트 루트에서 Node 22 이상과 Windows Chrome으로 실행한다. 앱 실행 자체에는 Node가 필요하지 않다.

```powershell
node --test tests/*.test.mjs
node tests/run-browser.mjs
```

수치 결과와 화면 자료를 다시 저장하려면:

```powershell
$env:LUCK_WRITE_AUDIT = '1'
node --test tests/fortune-final.test.mjs
$env:LUCK_QA_SCREENSHOTS = './tests/screenshots/detailed'
node tests/run-browser.mjs
```

브라우저 실행기는 루프백 임시 포트와 전용 임시 프로필을 사용하고 종료 시 정리한다. 외부 자료는 테스트 fixture로 고정되어 회귀 실행에 외부 운세/AI API를 호출하지 않는다.

## 남은 한계

독립 시각 검증은 3개 연도 표본이며 전 기간 오차 보증은 아니다. 출생 계산의 역사적 표준시·서머타임·태양시 보정, 대운·용신·지지 합충, 전문 해석 감수, 실제 모바일 기기 전체 검수와 운영 배포는 범위 밖이다. **계산 규칙과 데이터 연결을 검증했으며 운세 문구의 사건 예측 타당성을 검증한 것은 아니다.**
