# 과거 절기 추가 독립 대조

검증일: 2026-10-16. 실행순서의 **추가 검증 완료** 기록이다. 기존 KASI 2024·2026년 48건과 별도로, 과거 연도를 분산 선정해 앱에 포함된 lunar-javascript 1.7.7 ESM 엔진을 외부 기관 자료와 직접 비교했다. 엔진 출력이나 기존 후보 어댑터를 정답으로 사용하지 않았다.

## 범위와 결과

| 자료 | 선정 연도·범위 | 결과 |
| --- | --- | --- |
| 홍콩천문대(HKO) 역서 변환표 | 1901, 1910, 1920, 1930, 1940, 1950, 1960, 1970, 1980, 1990, 2000, 2010, 2020, 2025년의 24절기 | **336건 날짜 모두 일치** |
| 미 해군천문대(USNO) Seasons API 4.0.1 | 위 14개 연도 + 지원 시작 연도 1900년의 춘분·하지·추분·동지 | **60건 모두 절대 차이 60초 이내**, 최대 35초, 평균 16.55초 |
| 관련 회귀 검사 | 달력·사주 후보·실제 사주 모듈·평생운세·추가 과거 절기 | **29개 통과, 실패 0개** |

선정 기준은 지원 시작 연도와 외부 자료의 시작 연도, 이후 10년 간격, 최근 완료 연도 2025년이다. 비교 결과를 본 뒤 일치하는 연도만 고른 것이 아니다. 2026년 미래 절기는 이번 과거 자료 집계에 포함하지 않았다. 두 자료에 겹치는 절기가 있으므로 396개의 서로 다른 절기 사건을 검증했다고 표현하지 않는다.

## 비교 방법

- HKO 표는 **날짜 단위**다. 절기 이름 24개와 순서를 확인하고, 엔진 UTC+8 날짜와 비교한다. 한국 UTC+9 날짜를 홍콩 날짜에 그대로 대입하지 않는다. 이 결과만으로 절입 시각의 분·초 정확성을 판단할 수 없다.
- USNO는 `tz=0&dst=false`로 조회했다. API 문서상 시간대 기준은 UT1이다. 분 단위 기준값을 엔진 UTC+8 시각에서 8시간을 뺀 값과 비교했다. 테스트의 ISO `Z` 표기는 수치 비교용이며 과거 UT1과 UTC가 동일하다는 주장이 아니다. 원자료의 분 단위 정밀도와 시간척도·계산 모델의 차이가 포함된 비교이므로 35초를 엔진의 절대 천문학적 오차 상한으로 해석하지 않는다.
- 허용 범위는 기존 KASI 검사와 같은 60초를 사용했다. 관측된 차이에 맞춰 허용 범위를 늘리지 않았다.
- 최대 차이는 1901년 춘분과 동지에서 각각 +35초다. 춘분 기준값은 UT1 03-21 07:23, 엔진 환산값은 07:23:35이며, 동지는 12-22 12:36 대 12:36:35다.
- UTC+8에서 고정 UTC+9로 변환할 때 날짜가 다음 날로 넘어가는 경우가 9건 있었다. 예를 들어 1950년 곡우는 엔진 기준 UTC+8 04-20 23:59:06 → UTC+9 04-21 00:59:06이다. 이 9건은 **엔진 시간대 변환 확인**이며 한국 날짜를 별도 외부 자료로 확정한 9건은 아니다.
- 표본 14개 연도에서 앱의 `springBoundary()` 반환값도 같은 UTC+9 변환과 일치함을 확인했다. 이는 앱 연결 검사이며 별도 독립 시각 검증으로 세지 않는다.

## 출처와 재현

- [HKO 연도별 달력표](https://www.hko.gov.hk/en/gts/time/conversion.htm): 1901~2100년 제공. 사용한 개별 TXT URL은 manifest에 기록했다.
- [HKO 절기 자료의 시간대 안내](https://www.hko.gov.hk/en/gts/astronomy/Solar_Term.htm): 홍콩 시간 UTC+8. HKO는 절기 천문자료의 기반으로 HMNAO·USNO를 명시하므로, HKO와 USNO가 서로 완전히 독립된 두 계산 체계라고 주장하지 않는다. 여기서 독립 대조는 **검증 대상 앱 엔진 밖의 기관 자료와 대조**했다는 뜻이다.
- [USNO 계절 자료](https://aa.usno.navy.mil/data/Earth_Seasons), [API 문서](https://aa.usno.navy.mil/data/api): 1700~2100년 제공. 근일점·원일점은 절기가 아니므로 제외했다.
- [원본·조회 URL·SHA-256 목록](../tests/fixtures/historical-terms/manifest.json): 자료 29개를 보관했다. HKO TXT는 원본 바이트를 보존하고 ASCII 날짜·절기 열만 파싱한다. USNO JSON은 응답 내용을 UTF-8로 저장했다.
- [건별 비교 결과](./HISTORICAL_TERMS_RESULTS.json): 336건 날짜, 60건 시각, 차이와 집계.
- [오프라인 검증 코드](../tests/historical-terms.test.mjs): 원본 해시, 연도 목록, 절기 개수·이름·순서를 검사하므로 자료 누락이나 파싱 실패가 통과 건수에 묻히지 않는다.

프로젝트 루트, Node.js 24.13.1에서 실행했다. 해당 버전에서는 기존 문서의 `--experimental-default-type=module` 옵션이 지원되지 않아 아래처럼 실행한다.

```powershell
node tests/historical-terms.test.mjs
node tests/historical-terms.test.mjs --report
node --test tests/calendar.test.mjs tests/saju-candidates.test.mjs tests/saju-calculator.test.mjs tests/lifetime.test.mjs tests/historical-terms.test.mjs
```

일반 검증은 네트워크 없이 실행된다. 외부 원본을 다시 받으려면 `./tests/fetch-historical-terms.ps1`을 실행한다. 이는 fixture와 해시를 갱신하므로 변경분을 검토한 뒤 보고서를 다시 생성한다. 사이트 실행 중 외부 API 호출이나 의존성은 추가하지 않았다.

## 완료 판단과 남은 한계

과거 자료의 **추가 독립 대조 및 결과 기록** 조건은 충족했으므로 계획의 해당 항목을 체크했다. 기존 2024·2026 표본 및 엔진 생성 가능 범위 검사와 구분한다.

다만 1900~현재 모든 연도의 24절기 시각을 전수 대조하지 않았다. 특히 과거 입춘 등 12개 월 경계 절기의 분·초 정확성을 이번 HKO 날짜 자료로 확정할 수 없고, USNO 4절기는 그 공백을 채우지 못한다. 전 기간·모든 출생 시각의 정확성 보증, 과거 한국 표준시·서머타임·태양시 보정, 전문 사주 해석 감수는 이번 완료 범위가 아니다. 앱의 고정 UTC+9·자정 일주·절입 ±60초 불확실성 정책은 유지한다.
