# 운세 사이트 개발 가이드

## 1. 서비스 방향

- 가볍게 즐기는 운세 서비스이면서, 읽을거리와 실용적인 조언이 충분한 결과를 제공한다.
- 운세는 재미와 자기 성찰을 위한 콘텐츠로 안내한다. 확정적인 미래 예측이나 불안을 유발하는 표현은 피한다.
- 친근하고 이해하기 쉬운 말투를 사용하고, 결과를 지나치게 단정 짓지 않는다.

## 2. 제공할 메뉴

| 메뉴 | 제공 내용 | 구현 방향 |
| --- | --- | --- |
| 오늘의 운세 | 오늘의 흐름, 관계, 일·공부, 생활 조언, 실천 팁 | 사주 정보와 오늘 날짜를 해석 규칙에 연결 |
| 평생운세 | 인생 전반의 경향과 시기별 흐름 | 기본 사주 해석에 시기별 계산·콘텐츠를 추가 |
| 사주팔자 | 연주·월주·일주·시주와 오행 등 기초 정보 | 검증 가능한 만세력 계산과 용어 설명 제공 |
| 내 성향 | 행동 방식, 강점, 관계 방식, 스트레스 경향, 균형을 잡는 팁 | 계산 결과에 맞는 성향 문구 조합 |

성향과 운세 해석을 과학적으로 검증된 성격 진단이나 예측으로 표현하지 않는다.

**1차 개발 범위는 오늘의 운세·사주팔자·내 성향으로 확정한다.** 평생운세는 세 메뉴를 완성하고 결과와 콘텐츠를 검수한 다음 확장한다.

## 3. 논의한 구현 방식과 비용

| 방식 | 장점 | 필요한 작업·비용 |
| --- | --- | --- |
| 외부 운세 API | 제공 범위에 따라 계산과 기본 해석을 빠르게 확보 | API 이용료가 발생할 수 있으며, 제공 범위·이용 조건 확인 필요 |
| 자체 계산 + 저장된 해석 문구 | 결과가 일관되고 콘텐츠를 직접 관리 가능 | 계산 기능, 해석 문구, 연결 규칙을 개발할 초기 작업 필요 |
| 자체 계산 + AI 해석 | 계산 결과를 자연스러운 개인별 설명으로 확장 | AI API 입력·출력 토큰 비용과 결과 검수 필요 |
| 외부 운세 API + AI 해석 | API 결과에 추가 설명 제공 | 유료 서비스 사용 시 API 비용과 AI 비용이 각각 발생 |
| 외부 운세 API + 저장된 추가 콘텐츠 | API의 기본 해석에 사이트만의 설명과 팁 추가 | API 비용이 발생할 수 있고, 추가 콘텐츠 및 연결 규칙 필요 |

외부 API는 무료 범위나 요금제가 있을 수 있으므로 실제 후보를 확인하기 전에는 비용을 확정하지 않는다. 어떤 방식이든 서버·도메인 등 운영 비용은 별도다.

## 4. 현재 기준으로 삼을 구현 방향

**외부 운세 API와 런타임 AI API 없이, 자체 계산 + 저장된 해석 문구 방식으로 시작한다.** 이는 지금까지 논의한 내용을 바탕으로 한 초기 개발 기준이며, 외부 서비스 도입은 필요할 때 다시 검토한다.

개발 과정에서 AI의 도움으로 콘텐츠 초안이나 코드를 만드는 것과, 운영 중 사이트가 AI API를 호출하는 것은 구분한다. 미리 작성한 문구를 사이트에 저장하면 방문자가 운세를 조회할 때 AI 토큰 비용이 발생하지 않는다. 개발 도구 사용에 따른 비용은 별도다.

```text
생년월일·양력/음력·출생 시간 입력
    ↓
만세력 계산
    ↓
해석에 필요한 특징 추출
    ↓
규칙에 맞는 저장된 문구 선택
    ↓
영역별 해석과 실천 팁 표시
```

### 계산 기능

- 달력 계산을 처음부터 모두 개발하기보다, 적합한 만세력 라이브러리나 데이터를 조사하고 검증해 사용한다.
- 사용 후보의 라이선스, 지원 범위, 정확성을 확인한다. 아직 특정 라이브러리는 선정하지 않았다.
- 양력·음력 변환, 윤달, 절기 기준, 출생 시간, 시간대와 날짜 경계 등 계산 기준을 명시한다.
- 출생 시간을 모르는 사용자도 이용할 수 있도록 입력 옵션을 제공하고, 시간에 의존하는 해석 범위를 제한한다.
- 일간, 오행 분포, 십성 등 필요한 특징을 추출하되, 오행 개수만으로 성격이나 길흉을 단정하지 않는다.
- 같은 입력과 같은 기준에는 같은 계산 결과를 제공한다. 오늘의 운세는 서비스에서 정한 날짜·시간대 기준으로 갱신한다.

### 해석 문구와 연결 규칙

- 결과 전체를 몇 가지 만들어 무작위로 보여주는 대신, 기본 성향·오늘의 흐름·관계·일·공부·생활·주의점·실천 팁을 나누어 준비한다.
- 계산된 특징과 날짜별 흐름에 따라 문구를 선택한다. 사주 계산 결과와 콘텐츠용 선택 규칙은 구분해 관리한다.
- 서로 모순되는 문구가 함께 선택되지 않도록 우선순위와 제외 조건을 둔다.
- 문구는 코드와 분리된 데이터로 관리해 수정과 추가를 쉽게 한다.
- 내용의 깊이는 문구 수뿐 아니라 구체성, 조합의 일관성, 반복 관리로 확보한다.
- 금전·건강 등의 내용은 중대한 의사결정을 유도하거나 결과를 보장하지 않는 일반적인 생활 조언으로 작성한다.

예시:

> 생각을 행동으로 옮기는 힘이 있는 편이에요. 오늘은 속도를 내기 전에 주변 사람과 방향을 맞추면 일이 더 수월해질 수 있어요. 미뤄둔 일 하나를 골라 20분만 시작해 보세요.

위 문장은 콘텐츠 형식의 예시이며, 검증된 사주 해석 규칙을 의미하지 않는다.

## 5. 콘텐츠 작업과 역할

사용자가 계산 기능과 해석 문구를 전부 직접 만들 필요는 없다. 개발 지원 과정에서 다음 작업을 함께 수행할 수 있다.

- 만세력 라이브러리 조사와 계산 기능 구현
- 오늘의 운세·성향·관계·일·공부·생활 조언의 콘텐츠 초안 작성
- 계산 결과와 문구를 연결하는 규칙 구현
- 입력 화면과 결과 화면 구현
- 콘텐츠 수정이 쉬운 데이터 구조 구성

사용자는 서비스 분위기와 표현 수위를 정하고, 결과물을 확인해 수정 방향을 결정한다. 작성된 해석은 초안으로 검토한다. 전통 사주 해석의 전문성이나 정확성을 내세우려면 전문가 검수가 필요하다.

## 6. 초기 개발 순서

다음 작업은 `luck` 프로젝트의 현재 상태를 확인하고, 공통 입력 항목과 계산 기준을 정하는 것이다. 아래 내용은 개발 계획이며, 구현 완료를 의미하지 않는다.

1. **프로젝트 확인**
   - 기존 코드, 기술 구성, 실행 방법과 현재 구현 범위를 확인한다.
   - 확인한 구성에 맞춰 계산 기능과 콘텐츠를 어디에 배치할지 정한다.
2. **공통 입력 화면 구현**
   - 생년월일, 양력·음력 구분, 음력의 윤달 여부, 출생 시간을 입력받는다.
   - 출생 시간에 ‘시간 모름’ 옵션을 제공한다.
   - 입력값 검증과 잘못된 날짜에 대한 안내를 구현한다.
3. **사주 계산 기능 구현·검증**
   - 만세력 라이브러리를 선정하고 절기·시간대·날짜 경계 등의 계산 기준을 정한다.
   - 알려진 사례와 대표 입력으로 결과를 비교해 검증한다.
   - 사주팔자 결과와 오늘의 운세·내 성향에서 사용할 특징을 추출한다.
4. **해석 문구와 연결 규칙 작성**
   - 사주팔자 용어 설명, 성향·강점·관계 방식, 오늘의 분야별 운세와 실천 팁을 준비한다.
   - 문구를 별도 데이터로 저장하고 계산 결과에 연결한다.
   - 문구 선택의 우선순위와 모순을 방지하는 조건을 마련한다.
5. **결과 화면 구현·검수**
   - 오늘의 운세·사주팔자·내 성향 결과를 모바일에서도 읽기 편하게 구성한다.
   - 문구의 모순·반복, 출생 시간 미상, 양력·음력·윤달 입력 등 예외 상황을 확인한다.
   - 같은 입력의 결과 일관성과 오늘의 운세 날짜 갱신을 확인한다.

### 세 메뉴 완성 후 할 일

1. 실제 결과를 검토하며 설명의 가독성, 해석의 일관성, 콘텐츠의 다양성을 보강한다.
2. 평생운세의 제공 범위를 정하고 인생 전반의 기본 해석부터 확장한다.
3. 시기별 흐름까지 제공하려면 대운·세운 계산 기준과 해석 콘텐츠를 추가로 준비하고 검증한다.

## 7. 추후 외부 API를 도입할 때 확인할 사항

외부 API의 기본 결과에 저장된 설명과 생활 팁을 덧붙이는 방식도 가능하다. 이 경우 아래 항목을 확인한다.

- 계산뿐 아니라 해석 문구까지 제공하는지
- 오늘의 운세·평생운세·사주팔자·성향 메뉴를 얼마나 지원하는지
- 총운·관계·일 등의 분야별 결과나 분류 정보를 제공하는지
- 결과를 편집·재구성해 표시할 수 있는지
- 결과 저장과 재사용을 허용하는지
- 이용료, 호출 제한, 개인정보 처리 및 외부 전송 조건

긴 해석 글만 제공하는 API보다 분야별 결과와 분류 정보가 있는 API가 추가 콘텐츠를 연결하기 쉽다. 실제 공급자와 요금제는 아직 선정하지 않았다.

## 8. 기술 구성과 실행·배포

- 사용 기술: HTML, CSS, 바닐라 JavaScript
- 프로젝트 상태: 신규 프로젝트에 화면 확인용 대시보드 구현 완료. 실제 사주 계산과 개인별 해석은 미연결
- 배포 대상: GitHub Pages
- 초기 구성: 빌드 없이 배포할 수 있는 정적 사이트를 기본으로 한다.
- 사주 계산과 해석 문구 선택은 브라우저에서 수행하는 방향으로 구성한다.
- 로컬 개발은 개발 서버로 실행한다. GitHub Pages는 배포 후 사이트를 제공하는 환경이며, 로컬 실행과 구분한다.

패키지 구성은 외부 라이브러리와 개발 도구의 목록을 의미하며, 파일·폴더 구성과는 구분한다. 만세력 라이브러리는 브라우저 지원 여부와 계산 요구사항을 검토한 후 선정한다. 패키지 관리가 필요하면 `package.json`에 의존성과 실행 명령을 기록한다. 선택한 라이브러리가 빌드를 요구하면 빌드 도구를 추가한다.

GitHub Pages의 저장소 하위 경로에서도 동작하도록 CSS·JavaScript·데이터 경로를 구성한다. 예를 들어 HTML에서 `./css/style.css`와 같은 상대 경로를 사용한다.

### 파일 구성 초안

```text
luck/
├─ index.html
├─ saju.html
├─ personality.html
├─ css/
│  └─ style.css
├─ js/
│  ├─ common.js         # 공통 입력·임시 저장
│  ├─ today.js          # 오늘의 운세
│  ├─ saju.js           # 사주팔자
│  ├─ personality.js    # 내 성향
│  ├─ render.js         # 공통 카드 출력
│  ├─ data.js           # 예시 데이터
│  ├─ calculator.js     # 사주 계산
│  └─ interpreter.js    # 해석 문구 선택
├─ data/
│  └─ interpretations.json
└─ doc/
   ├─ GUIDE.md
   └─ IMPLEMENTATION_PLAN.md
```

JavaScript 모듈로 계산·해석·화면 처리를 분리한다. 위 구조는 초기 제안이며 라이브러리 선정과 실제 구현에 맞춰 조정할 수 있다.

## 9. 화면 구성과 디자인 기준

사용자가 제공한 대시보드 이미지를 디자인 참고로 삼는다. 이미지의 왼쪽 검정 사이드바를 **검정 상단 메뉴**로 변경하고, 나머지 영역은 카드 중심의 대시보드로 구성한다.

### 레이아웃

- 상단 메뉴: 사이트 이름 또는 로고, 오늘의 운세·사주팔자·내 성향 메뉴
- 입력 정보 영역: 입력한 생년월일 정보와 ‘정보 수정’ 버튼
- 요약 영역: 오늘의 핵심 메시지, 나의 일간, 대표 성향 등 요약 카드
- 상세 영역: 선택한 메뉴의 상세 해석과 오행 분포 등 계산 정보
- 조언 영역: 분야별 조언과 오늘의 실천 팁

각 메뉴의 내용에 맞게 카드 구성은 조정한다. 첫 방문에는 공통 입력 화면을 제공하고, 결과를 조회한 뒤 입력 정보를 수정할 수 있도록 한다.

```text
[로고]       [오늘의 운세] [사주팔자] [내 성향]

[입력한 생년월일 정보                 정보 수정]

[요약 카드]       [요약 카드]       [요약 카드]

[          상세 해석          ] [ 오행 분포 ]

[          분야별 조언 / 오늘의 실천 팁       ]
```

### 너비와 반응형 구성

- 대시보드의 최대 너비는 **1200px**로 설정하고 중앙에 배치한다.
- 1200px를 고정 너비로 사용하지 않고, 좁은 화면에서는 가용 너비에 맞게 줄어들도록 한다.
- 상단 메뉴 내부 콘텐츠도 대시보드와 같은 최대 너비와 정렬 기준을 사용한다.
- 데스크톱의 기본 좌우 여백은 20px, 모바일은 16px로 구성한다.
- 모바일에서는 카드를 한 열로 배치하고 상단 메뉴가 화면 밖으로 넘치지 않도록 대응한다.

```css
.dashboard {
  width: calc(100% - 40px);
  max-width: 1200px;
  margin: 0 auto;
}

@media (max-width: 600px) {
  .dashboard {
    width: calc(100% - 32px);
  }
}
```

위 CSS는 너비 기준 예시이며, 카드 열 수와 메뉴 배치는 실제 콘텐츠에 맞춰 구현한다.

### 디자인 스타일

- 검정: 상단 메뉴와 주요 강조 요소
- 연한 회색: 본문 배경
- 흰색: 해석과 정보 카드
- 라임색: 선택된 메뉴와 핵심 강조
- 민트색: 보조 강조와 차트
- 참고 이미지의 둥근 카드와 여백을 활용하되, 긴 운세 설명을 읽기 쉽도록 카드 높이와 본문 여백을 충분히 확보한다.
- 차트는 오행 분포처럼 실제 계산 정보가 있는 영역에 사용한다.

실행순서의 ‘계산 기능, 해석 데이터, 화면을 배치할 구조’는 파일·코드 구성에 해당한다. 이 절의 대시보드 레이아웃은 사용자가 보는 화면 구성에 해당하며, 두 기준을 함께 적용한다.

### 메뉴별 페이지 분리

오늘의 운세는 `index.html`, 사주팔자는 `saju.html`, 내 성향은 `personality.html`로 분리한다. 상대 경로 링크로 이동하고 공통 CSS와 입력 기능을 공유한다. 출생 정보는 `sessionStorage`에 임시 보관해 같은 탭의 이동·새로고침 때 복원한다. 서버로 전송하지 않으며 저장이 차단되면 현재 페이지에서만 사용할 수 있다. 실제 계산은 아직 미연결이다.
