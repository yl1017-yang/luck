# 분야별 상세 운세·월운 설계

확정일: 2026-10-16. 설계 버전: 1.0.0. 실행순서 9단계 산출물이며 **기능 구현은 10~12단계, 검증은 13단계에서 진행한다.** 이 문서의 결정은 사주 전반의 유일한 해석법이 아니라 이 서비스의 초기 제공 기준이다.

## 1. 제공 범위와 메뉴

| 위치 | 유지할 내용 | 추가할 내용 |
| --- | --- | --- |
| 사주팔자 `saju.html` | 네 기둥·일간·단순 오행 개수·용어 설명 | `./lifetime.html#annual-detail`로 ‘분야별 운세·월운 보기’ 링크 |
| 내 성향 `personality.html` | 일간 기반 행동·강점·관계·스트레스·균형 | 변경 없음. 연도별 풀이를 복제하지 않음 |
| 오늘의 운세 `index.html` | 날짜별 생활 제안과 실천 팁 | 변경 없음. 기존 날짜 해시를 연간·월운에 사용하지 않음 |
| 평생운세 `lifetime.html` | 인생 전반 여섯 영역·최대 다섯 세운 요약 카드 | 연도 선택 → 적용 세운 선택 → 총론·재물·직장/사업·가정/건강·이성/대인관계 → 양력 12개월 월운 |

네 메뉴와 HTML 분리를 유지하고 다섯 번째 메뉴는 만들지 않는다. 해시는 같은 페이지의 영역 이동에만 사용한다. 인생 경향은 ‘기본 성향’, 연간 상세는 ‘선택 기간의 해석’으로 제목을 구분한다. 기존 연도 카드의 요약은 상세 총론과 같은 주제를 사용하며, 상세 본문을 카드에 중복 출력하지 않는다.

새 상세의 표시 이름은 ‘분야별 운세·월운’, 월별 표기는 ‘월별 운세(월운)’다. 원국 전체를 종합한 전문 풀이, 토정비결, 대운으로 소개하지 않는다.

## 2. 해석에 사용할 값

초기 버전은 **확정된 출생 일간 D, 기간의 연간 십성 A, 기간의 월간 십성 M**을 사용한다. A와 M은 모두 D에 대한 천간의 십성이다. 월간을 연간에 비교한 십성이 아니다.

| 출력 | 입력·계산값 | 선택 규칙 | 적용 기간 |
| --- | --- | --- | --- |
| 기본 성향 | D와 D의 오행 | 기존 `DAY_MASTERS`·`LIFE_ELEMENTS` 재사용 | 조회 연도와 무관 |
| 연간 총론 | D, 연도 천간, A | `annual[A].overview`; 일간 기본 설명은 별도 영역 | 해당 세운의 입춘~다음 입춘 |
| 재물운 | A | `annual[A].wealth`: 예산·반복 지출·자원 배분 관점 | 위와 같음 |
| 직장·사업운 | A | `annual[A].work`: 역할·준비·협업·운영 관점 | 위와 같음 |
| 가정·건강운 | A | `annual[A].homeHealth`: 가족 소통과 휴식·생활 습관을 각각 문단으로 제공 | 위와 같음 |
| 이성·대인관계 | A | `annual[A].relationships`: 친밀한 관계·경계·소통 관점 | 위와 같음 |
| 월운의 주제·네 분야 | A, M | `monthly[M]`의 주제·분야별 설명 + `bridges[A][M]`의 연간 주제 연결 | 절기 월과 양력 월, 선택 연도, 출생일 이후 범위의 교집합 |
| 기간·근거 표시 | 연·월 간지, D, A, M, 절입 시각 | 계산값을 표시하고 선택 문구 ID와 분리 | 각 실제 적용 구간 |

지지는 간지 표시 및 월 구간 식별에만 사용한다. 원국의 연·월·시주, 지장간, 합충·형파해, 신강약·격국·용신, 오행 가중 점수는 해석 조건에 넣지 않는다. 대운·순역·시작 나이와 성별 입력도 추가하지 않는다. 향후 도입하려면 별도 설계·근거·검증 항목이 필요하다.

같은 일간과 같은 기간을 가진 사용자는 같은 상세 문구를 받을 수 있다. 출생 시각만 달라졌는데도 개인화를 연출하려고 문구를 바꾸지 않는다. 단순 오행 개수로 건강·부·직업 적합성을 판단하지 않는다.

## 3. 문구 체계와 적용 규칙

기존 `ANNUAL_READINGS`의 십성 10종 주제를 아래 기준으로 유지한다. 아래 명칭은 편집 주제이며 사건 예측 공식이 아니다.

| 십성 키 | 연간·월간 공통 편집 주제 |
| --- | --- |
| 비견 | 내 기준과 협력 |
| 겁재 | 역할과 경계 조율 |
| 식신 | 꾸준한 표현과 생산 |
| 상관 | 새로운 표현과 점검 |
| 편재 | 기회와 자원 살피기 |
| 정재 | 꾸준한 운영과 관리 |
| 편관 | 도전의 범위 정하기 |
| 정관 | 역할과 약속 정리 |
| 편인 | 관점과 탐색의 확장 |
| 정인 | 배움과 기반 다지기 |

연간 10종 각각 총론과 네 분야를 작성한다. 각 영역에는 `summary` 1문장, `paragraphs` 2~3문단(문단당 2~3문장), `opportunity`·`caution`·`action` 각 1개를 둔다. 글자 수를 채우기 위한 반복보다 분야에 맞는 설명을 우선한다. 월간 10종은 요약·네 분야별 1~2문장·주의점·실천 조언으로 간결하게 작성한다.

연간과 월간의 연결 문구는 10×10의 `bridges[A][M]` 100조합을 명시적으로 준비한다. 월운의 실천 방향은 M이 정하고 A는 그 행동의 맥락을 설명한다. 예를 들어 연간 정재·월간 편재이면 ‘유지할 예산 범위를 먼저 정한 뒤 새 제안의 조건을 살펴보기’처럼 연결한다. 이는 작성 형식의 예시이며 실제 콘텐츠 완료를 뜻하지 않는다.

선택 순서는 입력/범위 검증 → D 확정 확인 → 기간 계산 → A/M 결정 → 정확한 콘텐츠 키 조회 → 문구와 근거 반환이다. 난수·날짜 해시·이름·접속 순서·미확정 기둥을 사용하지 않는다. 월마다 억지로 다른 문구를 만들지 않으며 동일한 A/M 조합의 반복은 허용하고 설명한다.

콘텐츠 ID는 `annual.<십성키>.<영역>`, `monthly.<십성키>.<영역>`, `bridge.<연간십성키>.<월간십성키>`로 고정하고 새 데이터의 버전은 `1.0.0`에서 시작한다. 콘텐츠 객체에 `id`, `requires`, 본문을 포함하고 반환 근거에 `contentIds`, D/A/M, 실제 적용 기간, 버전을 남긴다. 근거 펼치기에는 일간·십성·적용 기간을 보여주고 내부 ID는 화면 본문에 노출하지 않는다.

필수 키 누락은 개발 검증 실패다. 런타임에는 해당 영역에 ‘이 해석을 준비하지 못했어요’와 계산된 기간만 표시하며 다른 십성의 문구로 대체하지 않는다. 정확한 키가 하나이므로 무작위 동률 선택이나 보편적 길흉 기본값이 없다. 연결 문구 누락 시 해당 월 구간 해석을 미제공 처리한다.

실천 행동은 월간의 한 방향으로 통일하고, 총론·연간 문구는 상황과 조건을 설명한다. 서로 반대되는 명령을 함께 내리지 않는다. 금전 획득·승진·혼인·임신·질병을 확정하지 않고 성별·직업·혼인 상태를 가정하지 않는다. 투자·진료 판단을 대신하는 조언을 작성하지 않는다. 계산 사실과 편집 해석을 각각 검증한다.

## 4. 조회 범위와 선택 상태

- 새 상세 화면의 선택 연도 Y는 **양력 연도**이며 정수 `max(1901, 양력 환산 출생연도)`~2050이다. 기본은 `Asia/Seoul` 현재 양력 연도다. 현재 연도가 지원 범위 밖이면 마지막 연도로 조용히 보정하지 않고 지원 범위 안내와 명시적 연도 선택을 제공한다.
- 이전 출생 연도는 선택 불가다. 출생 연도는 조회 가능하되 양력 출생일 00:00 이전 구간은 잘라낸다. 이 00:00은 일 단위 표시 시작점이지 시간 미상의 가상 출생 시각이 아니다. 출생일 당일은 일간 기반 풀이로 제공하며 출생 전 시각의 사건을 해석하지 않는다.
- 출생 전 월도 1~12월 목록에는 남기되 ‘출생 전 기간’ 상태로 두고 개인별 문구를 만들지 않는다. 출생 월은 출생일부터만 적용한다. 미래 연도는 2050년까지 선택 가능하며 출생 입력의 ‘미래 날짜 금지’와 구분한다.
- Y의 1월 1일~입춘 전에는 Y-1 세운, 입춘부터 12월 31일까지는 Y 세운이 적용된다. 화면에 두 적용 세운 탭을 만들고 출생일 이후 교집합이 없는 탭은 생략한다. 임의로 한 세운을 양력 연도 전체에 적용하지 않는다.
- 현재 연도 최초 조회에서는 현재 순간에 해당하는 세운 탭을 연다. 다른 연도 최초 조회는 Y 세운 탭을 연다. 각 탭 제목에 실제 적용 기간을 표시한다. 조회 순간이 입춘 ±60초 이내면 두 후보를 안내하고 자동으로 한 탭을 확정하지 않는다. 사용자가 탭을 직접 열어 읽는 것은 허용한다.
- 기존 연도 요약 카드의 ‘상세 보기’는 카드의 세운 연도 Y와 Y 세운 탭을 선택한다. 기존 요약에 나타날 수 있는 1900 세운 카드는 새 상세 선택 범위 밖이므로 상세 링크를 비활성화하고 이유를 표시한다. 기존 요약 계산은 유지한다.
- `luck.fortuneView.v1`에 `{ year, cycleYear, month }`만 sessionStorage로 저장한다. 출생 정보는 기존 키에 유지하고 URL에 넣지 않는다. 월은 1~12, 세운 연도는 선택 연도 또는 직전 연도이며 실제 유효 구간이 있어야 한다. 유효하지 않은 저장값은 기본 선택으로 초기화한다.
- 입력 수정 후 선택 연도가 여전히 유효하면 유지하고 아니면 현재 연도 기본 규칙으로 돌아간다. 저장 차단 시 현재 화면 메모리로 동작한다. 새로고침·메뉴 복귀는 유효한 선택을 복원한다. 직접 선택하거나 복원한 연도·탭·월은 시계 이벤트가 덮어쓰지 않는다.
- 기본 자동 선택 상태에서만 새해·입춘·월 변경 시 선택을 갱신한다. 모든 상태에서 현재 구간 표시와 경계 안내는 1분 간격·탭 복귀 때 갱신한다. 선택 연도가 과거/미래이면 ‘현재 구간’ 강조를 만들지 않는다.

## 5. 기간과 월운 계산 계약

모든 계산 구간은 **시작 포함·끝 제외 `[start, end)`**다. 순간은 ISO UTC로 반환하고 화면은 고정 UTC+9로 표시한다. 분 단위 표시에서도 ‘종료 시각 직전까지’임을 밝히며 실제 비교는 초 단위 계산값으로 한다. 절입 ±60초는 현재 구간 확정의 유예이며 구간 자체를 늘이거나 빈틈을 만드는 값이 아니다.

양력 1~12월은 표시용 묶음이다. 절기 월은 아래 절입에서 바뀐다. 24절기를 모두 월 경계로 사용하지 않는다.

| 월 경계 | 시작하는 월지 |
| --- | --- |
| 소한 | 축 |
| 입춘 | 인 |
| 경칩 | 묘 |
| 청명 | 진 |
| 입하 | 사 |
| 망종 | 오 |
| 소서 | 미 |
| 입추 | 신 |
| 백로 | 유 |
| 한로 | 술 |
| 입동 | 해 |
| 대설 | 자 |

Y년 양력 범위를 덮으려면 Y-1년 대설부터 Y+1년 소한까지 경계가 필요하다. 1901 조회에는 1900 대설, 2050 조회에는 2051 소한을 내부 경계로만 계산한다. 연간 2050 세운의 원래 종료 정보에는 기존처럼 2051 입춘을 사용한다. 2051년 콘텐츠나 출생일 지원은 추가하지 않는다.

절기 월별 간지는 기존 엔진의 정확한 월주 방식으로 얻고 연주처럼 입력 순간을 UTC+8로 변환한다. 각 구간 내부의 순간으로 간지를 구하는 것은 허용하지만, 월 전체를 임의의 15일 정오 하나로 계산하지 않는다. 구간 시작 직전/정각/직후의 월주를 별도로 검증한다.

표시 구간은 절기 월과 양력 월, 양력 Y년, 출생일 이후 범위를 교차하여 생성한다. 입춘에서 A도 전환한다. 12개월 배열은 항상 유지하되 월 안의 `segments`는 절입 전후로 나누며 출생 전 월은 빈 배열이다. 같은 절기 월이 인접 양력 월에 걸치면 같은 M과 해석 ID를 재사용하고 ‘이전 달부터 이어지는 구간’으로 안내한다.

예: Y년 1월은 `01-01~소한`과 `소한~02-01`로 나누고 둘 다 Y-1 세운을 사용한다. 2월은 `02-01~입춘`에 Y-1 세운, `입춘~03-01`에 Y 세운을 사용한다. 연간 탭을 변경해도 월운 각 구간의 A는 그 구간에 해당하는 세운을 따른다.

원래 절기 구간 `sourceStart/sourceEnd`와 표시용 교집합 `start/end`를 모두 보관한다. 조회 시각이 어느 절입이든 ±60초 이내이면 `nearBoundary=true`, `activeSegmentId=null`과 양쪽 후보 ID를 반환한다. 정각부터 새 간지를 적용하는 계산 규칙과 ‘지금 어느 쪽인지’ 확정을 유예하는 화면 규칙을 구분한다.

## 6. 미확정·오류 상태

출생 연·월·시주가 미확정이어도 D가 확정되어 있으면 이번 상세와 월운은 제공할 수 있다. `partial` 안내와 제외된 기둥을 함께 전달한다. 시주를 추정하거나 미확정 기둥에서 십성을 구하지 않는다. D가 없으면 `unavailable-day-master`로 상세를 제공하지 않는다.

입력 없음은 `null`, 잘못된 연도·조회 시각은 검증 오류, 지원 밖 연도는 범위 안내다. 일부 기간 계산 실패 시 그 달을 정상 빈 결과로 보이지 않고 `calculation-error`로 표시한다. 나머지 독립적으로 계산된 영역은 표시할 수 있으나 실패를 무관한 정상 문구로 덮지 않는다.

## 7. 구현 책임과 데이터 구조

2026-10-16: `js/fortune-periods.js`는 10단계, `js/fortune-interpreter.js`와 연간·월간 콘텐츠는 11단계에서 구현했다. [계산 검증 기록](./FORTUNE_PERIODS_VALIDATION.md)과 [콘텐츠 검수 기록](./DETAILED_FORTUNE_CONTENT_VALIDATION.md)을 참고한다. 12단계 화면 연결도 완료했다. [UI 검수 기록](./DETAILED_FORTUNE_UI_VALIDATION.md)을 참고한다.

| 파일 | 역할 |
| --- | --- |
| 기존 `js/saju-calculator.js` | `annualPillar`, `springBoundary`, `tenGodForStems` 재사용. 기존 공개 함수 동작 유지 |
| 새 `js/fortune-periods.js` | 절기 월·양력 월 교집합·선택 연도 세운 계산. 순수 `calculateFortunePeriods(result, year, now)` |
| 새 `js/fortune-interpreter.js` | `interpretDetailedFortune(result, periods)`로 A/M 콘텐츠 선택·근거 반환 |
| 새 `js/content/annual-details.js` | 연간 십성 10종×총론/네 분야 |
| 새 `js/content/monthly-details.js` | 월간 10종과 연간/월간 연결 100조합 |
| 기존 `js/content/lifetime.js` | 인생 경향과 연간 주제 요약 유지. 상세 총론과 주제 일치 검사 |
| 기존 `js/lifetime.js`, `lifetime.html` | 연도·세운 탭·월 선택, 저장, 결과 렌더링 |
| 기존 `saju.html` | 상세 링크만 추가. 공통 입력과 네 기둥 계산은 유지 |

계산 반환 구조의 필수 필드:

```text
year, range { start, end }, dayMaster, partial, excludedPillars
annualPeriods[] { id, cycleYear, pillar, tenGod, sourceStart, sourceEnd, start, end }
months[12] { month, status, segments[] }
segment { id, annualPeriodId, pillar, tenGod, sourceStart, sourceEnd, start, end }
current { nearBoundary, activeSegmentId, candidateSegmentIds[] }
```

`annualPeriodId`가 A를 결정하고 segment의 `tenGod`이 M이다. ID는 원래 절기 구간과 표시 구간 시작으로 안정적으로 생성한다. 해석 반환은 이를 보존하고 `version`, `annualReadings`, `monthlyReadings`, `contentIds`, `basis`를 추가한다. 화면 선택 상태는 계산 모듈의 전역 변수로 두지 않는다.

## 8. 후속 검증의 수용 기준

- 1901 하한·2050 상한·출생 전 연도 거부, 출생 연도 월별 잘라내기, 범위 밖 현재 연도의 명시적 선택을 확인한다.
- 12개월을 모두 반환하고 유효 구간 합집합이 표시 범위와 같으며 중복·공백이 없어야 한다. 이전 대설·다음 소한 및 2051 입춘 계산은 내부 경계로 한정한다.
- 입춘 전/후 A 변경, 12절입 전/정각/후 M 변경, ±60초 양쪽 후보, 윤년 2월, UTC+9 날짜 이월을 확인한다.
- 독립 절입 시각 자료를 사용하고 날짜 단위 HKO 비교와 시각 단위 검증을 구분한다. 기존 표본 결과를 전 기간 오차 보증으로 사용하지 않는다.
- D 10종·연간/월간 천간 10종의 십성 조합을 검증하고 콘텐츠 키 10종×5영역, 월간 10종 및 연결 100조합 누락을 검사한다.
- 이름 변경·양음력 등가 입력·시간 미상에도 같은 D와 같은 기간이면 문구가 같아야 한다. 기본 성향은 연도 선택으로 바뀌지 않는다.
- 문구 누락·저장 차단·손상 선택값·입력 변경·시계 이벤트에서 정의한 상태를 확인한다. 기본 자동 선택과 사용자 선택 유지를 구분한다.
- 실제 화면의 문단 가독성·키보드 월 선택·기간 안내·반복 문구·모순을 검수하고 기존 테스트 회귀를 확인한다.

9단계 완료는 위 설계와 관련 기준 문서 반영이다. 실제 데이터 작성량, 기능 테스트 결과, 브라우저 검수는 10~13단계 완료 기록으로 남긴다.
