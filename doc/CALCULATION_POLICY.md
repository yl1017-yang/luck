# 입력 항목과 계산 기준

확정일: 2026-10-15. IMPLEMENTATION_PLAN.md의 2단계에서 정한 기준이다. 현재 `js/saju-calculator.js`로 입력과 실제 사주 계산을 연결했고, 표본·경계 검증 결과와 과거 전 기간 독립 검증의 한계는 SAJU_VALIDATION.md에 기록했다.

## 1. 공통 입력

| 항목 | 기준 |
| --- | --- |
| 이름 또는 별명 | 선택, 공백 정리 후 최대 20자. 제목에만 사용하며 계산에 사용하지 않음 |
| 생년월일 | 필수. 선택한 달력 기준의 연·월·일 |
| 달력 구분 | 양력 또는 음력, 기본값 양력 |
| 윤달 여부 | 음력일 때만 표시. 기본값 일반달이며 양력으로 변경하면 해제 |
| 출생 시간 | 24시간제 시·분 입력. 임의의 기본 출생 시간을 넣지 않음 |
| 시간 모름 | 선택 시 시간 입력을 비활성화하고 계산용 시간은 null로 전달 |

세 메뉴에서 동일한 입력과 검증 모듈을 공유한다. 양력·음력 모두 연·월·일 드롭다운으로 선택한다. 월별 일수·윤달 및 양력 환산 후 미래 여부를 반영해 가능한 날짜만 표시한다. 내부 저장 형식은 YYYY-MM-DD를 유지한다. 윤달 체크는 해당 연도에 선택 가능한 윤달이 있을 때 활성화되며 체크하면 윤달에 해당하는 월만 선택할 수 있다.

## 2. 출생 시간 미상

시간을 모르면 정오 등 임의의 시각을 넣지 않는다. 시주와 시간에 의존하는 해석을 제외하고 확인 가능한 정보만 제공한다. 시간 미상은 계산 결과에 별도 상태로 남긴다. 사주팔자 화면은 실제 결과에서 시주를 빈 값으로 표시한다. 절입 당일 연·월주가 달라질 경우 불확실한 기둥도 빈 값으로 구분한다.

## 3. 지원 생년월일 범위

- 목표 계산 범위는 **양력으로 환산한 1900-01-01부터 한국 시간 기준 오늘까지**다.
- 양력 입력은 실제 날짜, 범위, 미래 여부를 즉시 검증한다.
- 음력 입력은 1900년부터 올해까지, 1~12월·1~30일 및 입력 형식을 검사한 뒤 korean-lunar-calendar 0.4.0으로 실제 날짜·윤달 여부를 검증한다.
- 양력 환산 후 1900-01-01부터 오늘까지인지 검사한다. 라이브러리의 양력 상한은 2050-12-31이며 이를 초과하는 날짜는 거부한다. 음력 변환 성공은 사주 계산 성공과 구분한다.
- 1900년 이전의 음력 연도는 초기 입력 범위에서 제외한다. 연도 경계의 음력 입력도 환산 후 최종 범위를 확인한다.
- 라이브러리가 목표 범위를 충족하지 못하면 임의로 계산하지 않고, 지원 범위를 재검토해 문서와 안내를 함께 수정한다.

## 4. 출생지와 시간대

- 1차 대상은 한국 출생이며 해외 시간대 선택과 자동 변환은 지원하지 않는다.
- 계산 입력은 **고정 UTC+9 한국 표준시**로 취급한다.
- 역사적인 표준시 변경·서머타임 보정, 출생지 경도에 따른 태양시 보정은 1차 범위에서 제외한다. 과거 출생 사례에서 보정을 적용하는 만세력과 결과가 다를 수 있음을 안내한다.
- ‘오늘’ 날짜 표시와 갱신은 `Asia/Seoul`을 사용한다. 과거 출생 시각의 고정 오프셋 정책과 현재 날짜의 시간대 처리를 구분한다.

## 5. 절기와 날짜 경계

다음은 서비스가 채택하는 해석상의 선택이며 유일한 사주 계산 방식이라고 주장하지 않는다.

- 음력 입력은 양력으로 환산한 후 같은 기준으로 계산한다.
- 연주 경계는 양력 1월 1일이나 음력 설 대신 입춘의 절입 시각을 사용한다.
- 월주 경계는 음력 초하루 대신 해당 월의 절입 시각을 사용한다.
- 절입 시각은 계산용 UTC+9 기준으로 정렬하며 경계 시각부터 새 연·월을 적용한다.
- 일주는 **00:00**에 변경한다. 23:00에 다음 일주로 넘기는 방식은 채택하지 않는다.
- 시지는 자시 23:00~00:59부터 두 시간 단위로 구분한다. 시주의 천간은 위 00:00 일주 경계 정책과 일관되게 산출한다. 라이브러리가 다른 유파를 기본값으로 쓰는지 확인한다.
- 23시 전후·자정 전후·절입 전후를 필수 비교 사례로 삼는다. 시간 미상으로 절입 전후 판단이 달라지면 연·월주를 하나로 단정하지 않고 경계 불확실 상태로 안내한다.
- 절기 시각의 자료 출처와 제공 정밀도, 비교 결과는 3단계에서 기록한다. 현재 임의의 절기 시각이나 사주 결과를 생성하지 않는다.
- 실제 입력이 계산된 절입 시각 ±60초에 걸리면 분 단위 입력과 참고자료 정밀도를 고려해 연·월주 중 달라지는 기둥을 확정하지 않는다. 양쪽 후보와 불확실성 이유를 반환한다. 이는 과거 모든 절기의 오차 상한을 보장하는 값이 아니다.

## 6. 오늘의 운세 갱신

- 한국 시간 00:00에 날짜 키가 변경된다.
- 날짜 키는 한국 시간 YYYY-MM-DD를 사용하고, 이후 해석 선택에 입력 특징과 함께 전달한다.
- 현재 화면 날짜는 1분 간격과 탭 복귀 시 갱신하며 날짜 키 변경 시 오늘의 운세도 갱신한다.
- 같은 입력과 같은 날짜·콘텐츠 버전에는 같은 결과를 제공한다. 날짜별 생활 주제를 선택하며 사건 예측을 계산하는 것은 아니다.

## 7. 입력 정보 저장

- `sessionStorage`의 `luck.birthProfile.v1`에 이름과 출생 정보를 임시 보관한다.
- 같은 탭의 페이지 이동·새로고침 시 입력과 제목을 복원한다. 서버 전송·localStorage 영구 보관은 하지 않는다.
- 시간 미상은 birthTime: null로 정규화한다. 기존 저장 데이터도 복원 시 같은 기준으로 정규화한다.
- 저장이 차단되면 현재 화면만 적용하고, 손상되거나 범위 밖인 데이터는 복원하지 않는다.
- 2단계 완료는 요구사항 확정을 의미한다. 실제 만세력과 음력 검증·개인별 해석 구현 완료를 의미하지 않는다.

## 8. 분야별 상세·월운의 확정 설계 (2026-10-16)

9단계 설계의 계산 부분은 10단계에서 `js/fortune-periods.js`로, 콘텐츠 선택은 11단계에서 `js/fortune-interpreter.js`로 구현했다. 선택 UI·저장·화면 연결은 12단계에서 구현했다. 전체 계약과 예외는 [상세 설계](./DETAILED_FORTUNE_SPEC.md), 실행 결과는 [계산 검증 기록](./FORTUNE_PERIODS_VALIDATION.md)과 [콘텐츠 검수 기록](./DETAILED_FORTUNE_CONTENT_VALIDATION.md)을 따른다.

- 새 상세의 선택 연도는 양력 기준 `max(1901, 양력 환산 출생연도)`~2050, 기본은 한국 현재 양력 연도다. 기본 연도가 범위 밖이면 안내와 명시적 선택을 제공한다.
- 선택 연도 1월 1일~입춘 전에는 이전 세운, 입춘부터 연말에는 해당 세운을 연결한다. 두 적용 기간을 분리하고 한 세운을 양력 연도 전체에 적용하지 않는다.
- 출생 연도는 출생일 00:00부터 표시한다. 이는 일 단위 콘텐츠 표시 범위이며 가상 출생 시각이 아니다. 이전 월은 ‘출생 전 기간’으로 표시한다.
- 월운은 출생 일간과 절기 월의 천간을 비교한 십성을 사용한다. 소한·입춘·경칩·청명·입하·망종·소서·입추·백로·한로·입동·대설을 경계로 한다.
- 절기 월과 양력 월의 교집합으로 1~12월 목록을 구성한다. 모든 기간은 시작 포함·끝 제외이며, 한 양력 월 안에서도 절입 전후를 나눈다.
- 1901년 1월 연결에는 1900 대설, 2050년 12월 연결에는 2051 소한을 내부 경계로 사용한다. 2050 세운 원래 종료는 2051 입춘이며, 2051년 조회 지원으로 확장하지 않는다.
- 고정 UTC+9·자정 일주·±60초 경계 유예를 유지한다. 현재 구간 강조만 유예하고 계산 구간을 늘이거나 줄이지 않는다.
- 미확정 연·월·시주는 해석에 사용하지 않는다. 확정된 일간이 있으면 상세 제공이 가능하며 부분 결과 안내를 유지한다.
- 새 조회 선택은 `luck.fortuneView.v1`에 연도·세운 탭·월만 임시 저장한다. 기존 출생 정보 키는 유지하며 유효하지 않은 선택값은 기본 규칙으로 초기화한다.

13단계 종합 검증 완료: KASI 2024~2026 월 경계 36건은 분 단위 참고값 대비 최대 28초 차이로 60초 허용 범위 안이었다. 1901~2050 구간 생성·연속성 검사와 독립 시각 표본 대조는 구분한다. 전 기간 시각 정확성 보증이 아니다. 출처·재현 방법·한계는 [종합 검증 보고서](./DETAILED_FORTUNE_FINAL_REVIEW.md)에 기록했다.

## 9. 原局(원국) 상세의 확정 설계 (2026-10-19)

14단계 [원국 상세 설계](./NATAL_DETAIL_SPEC.md)를 확정했다. 특징 계산 구현은 15단계다. 기존 출생 지원 범위·고정 UTC+9·자정·시간 미상·절입 ±60초와 반환 계약을 유지한다.

- 일간을 모든 천간·지장간 십성 비교 기준으로 사용한다. 일간 자체는 self로 표시하고, 다른 위치의 동일 천간은 비견으로 계산한다.
- 지장간은 버전 고정 표 `hidden-stems-lunar-1.7.7-v1`을 채택한다. 12지지 28항목의 본기·중기·여기는 채택 배열 순서에 붙인 서비스 표시 규약이며 사령 기간이나 세력 가중치가 아니다. 정확한 표·출처·관행 차이는 설계 3.2절을 따른다.
- 표면 오행 수는 확정 기둥의 천간·지지 대표 오행을 각각 1개씩 집계한 값이다. 지장간을 합산하거나 강약 점수로 바꾸지 않는다.
- 계절은 확정 월지 寅卯辰/巳午未/申酉戌/亥子丑에서 봄/여름/가을/겨울로 정한다. 월주 미확정 시 계절도 미제공한다. 辰未戌丑의 대표 오행 토와 계절 구분을 함께 표시한다.
- 미확정 기둥의 후보는 근거 안내에만 사용한다. 원국 계산에서 대운·용신·신강약·격국·합충·신살은 파생하지 않는다. 표·십성 연결의 독립 참고 대조와 구현 검증은 15~18단계에서 수행한다.

15단계 구현 완료(2026-10-19): `calculateNatalFeatures(result)`는 확정 기둥의 십성·지장간·계절·표면 집계·해석 가능 여부를 반환한다. 신규 12개·전체 75개 검사 통과. 입력 구조·집계·정책 불일치는 거부하고 후보는 집계에 넣지 않는다. 자세한 계약과 독립 검증의 남은 범위는 [특징 계산 검증 기록](./NATAL_FEATURES_VALIDATION.md)을 참고한다. 해석 문구·화면은 16~17단계에서 연결한다.

16단계 해석 선택 구현 완료: `interpretNatalDetails(features)`는 특징 버전·정책·십성·지장간·계절·맥락·가용 상태를 검증한 뒤 원고를 연결한다. 계산 특징을 바꾸거나 후보 기둥을 사용하지 않는다. 기둥별 사실은 `facts`와 section별 `basis`에, 편집 문구는 ID·조건을 가진 `blocks`에 구분해 반환한다. 17단계 화면 연결 전이며 [콘텐츠 검수 기록](./NATAL_CONTENT_VALIDATION.md)을 참고한다.

17단계 화면 연결 완료: 출생 정보 입력/복원 때 특징과 해석을 다시 계산하고 `js/natal-view.js`에서 출력한다. 시계 이벤트는 원국을 바꾸지 않는다. 시간 미상·절입 경계의 제외 항목과 맥락 선택 사유, 표면 집계와 지장간의 구분을 표시한다. [화면 검수 기록](./NATAL_UI_VALIDATION.md)에 예외·복원·반응형 확인 결과를 기록했다. 18단계 종합 검증도 완료했다. [최종 보고서](./NATAL_FINAL_REVIEW.md)를 참고한다.


## 18단계 종합 검증 반영 (2026-10-19)

전체 94개 검사와 Chrome 3개 스크립트가 통과했다. 독립 참고 지장간 12지지·28항목 구성 일치와 나열 순서 차이 5건을 확인했다. 본기·중기·여기는 앱 채택 순서의 표시 규약이며 사령·세력 비율이 아니다. 십성 외부 명시 사례 14건과 별도 규칙표 100관계, 육십갑자 콘텐츠 60종·전통 절기 계절 구분도 확인했다. 외부 실제 날짜 전수 대조와 구분한다. [최종 검증 보고서](./NATAL_FINAL_REVIEW.md)와 [대조 JSON](./NATAL_REFERENCE_RESULTS.json)에 출처·대표 출력·재현 방법·한계를 보관했다. 전문 감수·예측 타당성·전 기간 독립 시각 검증·배포는 별개이며 완료로 기록하지 않는다.
