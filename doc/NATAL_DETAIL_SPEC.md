# 사주팔자 상세 해석 범위와 판단 기준

확정일: 2026-10-19. 설계 버전 `1.0.0`. 실행순서 14단계 산출물이다. 특징 계산은 15단계, 콘텐츠는 16단계, 화면은 17단계, 종합 검증은 18단계에서 구현한다. 이 문서는 서비스가 채택할 계산·편집 규칙이며 전통 사주의 유일한 판단법이나 해석의 예측 타당성을 확정하는 자료가 아니다.

## 1. 현재 구현 조사와 부족한 설명

| 대상 | 현재 확인한 동작 | 상세 확장에서 보완할 부분 |
| --- | --- | --- |
| `saju.html`, `js/saju.js` | 네 기둥·한글 독음·부분 결과 안내·연간 상세 링크, `#saju-explanations` 카드 | 개인별 상세를 먼저 보여주고 공통 용어는 별도 펼치기로 이동 |
| `js/saju-calculator.js` | `calculateSaju()`의 profile·dates·pillars·features·uncertainty·policy·engine | 확정된 기둥만 사용해 파생 특징 생성. 기존 반환 계약 유지 |
| `js/interpreter.js`의 `interpretBirth()` | 일간 설명 1개, 오행 개수 설명 1개와 `GLOSSARY` 4개를 합쳐 사주 카드 6개 반환 | 일주·위치별 십성·지장간·계절·분야별 근거 설명이 없음 |
| `js/content/interpretations.js` | 일간 10종의 성향·생활 조언, 오행·공통 용어 | 일주 60종 및 원국 상세 전용 콘텐츠 추가, 기존 성향 문구와 중복 조정 |
| 기존 연간 상세·월운 | `fortune-periods`·`fortune-interpreter`가 조회 기간별 주제 제공 | 원국 상세는 출생 특징 고정. 연간/월운의 A/M을 원국 해석 조건으로 사용하지 않음 |

현재 오행 수는 확정된 천간·지지의 대표 오행을 각각 1개씩 센 값이다. 지장간 포함 수치·계절 가중치·신강약 점수가 아니다. 상세에서도 이 정의를 유지한다.

## 2. 제공 범위와 메뉴

`saju.html` 한 페이지에 네 기둥 → 원국 요약 → 일간·일주 → 기둥별 십성·지장간 → 계절·오행 → 분야별 설명 → 공통 용어 순으로 배치한다. 메뉴 4개와 기존 상대 경로, 연간 상세 링크를 유지한다.

- 일간 10종: 전통적 이미지·행동 관점·돌아볼 강점과 주의점.
- 일주 60종: 확정된 일간과 일지의 조합 설명. 일지 본기의 일간 대비 십성을 함께 제시하되 배우자 성격·결혼 시기·수명으로 연결하지 않는다.
- 천간 십성: 연·월·시 천간과 일간의 관계를 각각 표시한다. 일간 칸은 비교의 기준으로 표시한다.
- 지장간: 확정된 각 지지의 고정 목록과 각 천간의 십성·순서·채택 표를 제공한다.
- 계절: 확정된 출생 월지에서 4계절과 절기 월의 위치를 설명한다. 봄/목·여름/화·가을/금·겨울/수는 계절 상징으로 설명하며 토는 계절 말 월지의 대표 오행으로 별도 표시한다.
- 분야: `overview` 원국 요약, `temperament` 성향과 강점/주의, `workResources` 일·재물/자원 관리, `relationships` 이성·대인관계/소통, `dailyBalance` 가정·생활/휴식 관리의 5영역.

신강·신약·격국·용신·희기신·지지 합충/형파해·신살·12운성·대운·순역·시작 나이·토정비결은 범위 밖이다. 향후 추가하려면 별도 판단법·출처·관행 차이·불확실성·검증 사례를 먼저 정한다. 추가 성별·혼인·직업 입력은 받지 않는다.

## 3. 계산 기준

### 3.1 일간·일주·십성

기존 고정 UTC+9·자정 일주·분 단위 입력·절입 ±60초·한국 음력 변환 정책을 유지한다. 출생 지원 범위는 기존 양력 환산 1900년부터 한국의 오늘까지이며 라이브러리 상한은 2050-12-31이다. 연간 상세 조회의 1901 하한을 출생 원국에 적용하지 않는다.

일간 D는 `pillars.day.stem`이다. 일주 P는 확정된 `pillars.day.hanja`를 그대로 사용하며 60갑자에 포함되는지 검증한다. 엔진의 원본 시주나 23시 일주로 다시 계산하지 않는다.

십성은 기존 `tenGodForStems(D, X)`를 재사용한다. 오행 순환 목→화→토→금→수와 양/음(甲丙戊庚壬 / 乙丁己辛癸)을 기준으로 한다.

| X와 D의 관계 | 같은 음양 | 다른 음양 |
| --- | --- | --- |
| 같은 오행 | 비견 | 겁재 |
| D가 생하는 오행 | 식신 | 상관 |
| D가 극하는 오행 | 편재 | 정재 |
| D를 극하는 오행 | 편관 | 정관 |
| D를 생하는 오행 | 편인 | 정인 |

천간 위치는 연·월·일·시 순이다. 일간 자체의 항목은 `kind: 'self', tenGod: null`, 화면에는 ‘일간·나의 기준’으로 표시한다. 연·월·시 또는 지장간에서 D와 같은 천간은 실제 비교 결과인 비견으로 표시한다. 기둥 위치를 부모·배우자·자녀의 운명이나 특정 나이 사건으로 단정하지 않는다.

### 3.2 지장간 고정표

채택 표 ID는 `hidden-stems-lunar-1.7.7-v1`. [lunar-javascript v1.7.7 원본](https://github.com/6tail/lunar-javascript/blob/v1.7.7/lunar.js)의 `LunarUtil.ZHI_HIDE_GAN`과 로컬 `js/vendor/lunar-javascript/lunar.mjs`를 확인했다. [공식 EightChar 설명](https://6tail.cn/calendar/lunar.bazi.html)은 지장간과 그 십성이 1~3개 항목으로 반환됨을 설명한다. 외부 문구를 해석 콘텐츠로 복사하지 않는다.

| 지지 | 채택 배열·표시 순서 | 본기 | 중기 | 여기 |
| --- | --- | --- | --- | --- |
| 子(자) | 癸(계) | 癸 | — | — |
| 丑(축) | 己(기)·癸(계)·辛(신) | 己 | 癸 | 辛 |
| 寅(인) | 甲(갑)·丙(병)·戊(무) | 甲 | 丙 | 戊 |
| 卯(묘) | 乙(을) | 乙 | — | — |
| 辰(진) | 戊(무)·乙(을)·癸(계) | 戊 | 乙 | 癸 |
| 巳(사) | 丙(병)·庚(경)·戊(무) | 丙 | 庚 | 戊 |
| 午(오) | 丁(정)·己(기) | 丁 | 己 | — |
| 未(미) | 己(기)·丁(정)·乙(을) | 己 | 丁 | 乙 |
| 申(신) | 庚(경)·壬(임)·戊(무) | 庚 | 壬 | 戊 |
| 酉(유) | 辛(신) | 辛 | — | — |
| 戌(술) | 戊(무)·辛(신)·丁(정) | 戊 | 辛 | 丁 |
| 亥(해) | 壬(임)·甲(갑) | 壬 | 甲 | — |

**본기·중기·여기는 이 서비스에서 위 배열의 첫째·둘째·셋째에 붙이는 표시 규약이다.** 원본은 천간 배열을 제공하며 개별 항목의 한국어 역할명까지 검증해 주는 것은 아니다. 2개 항목의 둘째를 여기로 부르거나 절입 후 날짜에 따라 사령을 배분하는 관행을 혼합하지 않는다. 사용자 근거 펼치기에 ‘채택 표 순서이며 날짜별 사령·세력 비율을 뜻하지 않음’을 표시한다. 18단계에서 외부 독립 참고표와 순서·명칭 차이를 대조한다. 같은 엔진의 로컬/원본 비교만으로 독립 검증 완료라고 기록하지 않는다.

지장간은 위치별 목록으로 보관한다. 같은 천간이 다른 기둥에 있으면 각 위치에 남기고, 해석 주제를 묶을 때만 중복을 합친다. 숫자 가중치·통근 판정·지장간 포함 오행 총점·십성 순위는 만들지 않는다. 표면 오행 8글자 이하 집계와 합산하지 않는다.

### 3.3 계절과 집계

| 확정 월지 | 계절 | 절기 월 시작 |
| --- | --- | --- |
| 寅·卯·辰 | 봄 | 입춘·경칩·청명 |
| 巳·午·未 | 여름 | 입하·망종·소서 |
| 申·酉·戌 | 가을 | 입추·백로·한로 |
| 亥·子·丑 | 겨울 | 입동·대설·소한 |

`season`은 월지가 확정된 때만 반환한다. 음력 월·양력 월·현재 계절로 추측하지 않는다. 辰未戌丑은 각각 해당 계절의 마지막 절기 월이고 대표 오행 토라는 사실을 별도로 설명한다. 계절 설명은 상징적 배경이며 ‘왕성/약함’ 점수·건조/한랭 체질·질환·필요한 용신을 산출하지 않는다.

표면 오행은 기존 `features.elements`를 검증해 복사한다. 확정된 천간·지지 각각 1개, 합계는 확정 기둥 수×2다. 표면 0은 ‘집계에서 나타나지 않음’으로 표현한다. 지장간에 같은 오행이 있을 수 있으므로 ‘원국에 완전히 없음’이라고 쓰지 않는다.

## 4. 해석 조건과 조합

| 영역 | 필수 특징 | 선택과 출력 근거 |
| --- | --- | --- |
| 일간 상세 | D | D 10종의 정확한 키. 기존 성향 자료와 연결되는 부분의 출처 ID 보존 |
| 일주 상세 | P, 일지 본기 십성 H | P 60종의 독립 작성 문구 + 일간·일지·H 근거. P만으로 전체 원국 평가 금지 |
| 기둥 천간 십성 | D, 각 확정 천간 | 위치별 실제 십성, 같은 유형은 주제 설명 1회와 모든 위치 목록 |
| 지장간 | D, 각 확정 지지 | 고정표의 천간별 십성. 반복 항목은 위치별 사실로 유지 |
| 계절·오행 | 확정 월지 / 표면 집계 | 계절 4종 설명과 실제 월지·대표 오행, 표면 수와 지장간 구분 안내 |
| 5개 분야 | D, H; 선택적으로 C와 S | D별 기본 문구 + 기준 십성 C의 맥락 + 계절 S 보조 설명. 사용된 P·위치·C·S를 표시 |

C는 ‘해석 맥락을 읽는 순서’로 정하며 우세 십성·강약을 뜻하지 않는다. 월간 천간이 확정되면 그 십성, 아니면 일지 본기의 십성 H를 사용한다. 선택 이유를 각각 `month-stem` / `day-branch-main`으로 반환한다. 연·시 십성과 나머지 지장간은 기둥 설명에서 모두 보여주지만 임의 점수로 분야의 주제를 교체하지 않는다. D와 H를 확인할 수 없으면 분야 해석을 제공하지 않는다.

분야별 행동은 D의 기본 문구가 정하고 C는 적용 조건·점검 질문만 보완한다. S는 분야 카드 전체에 한 번 붙는 계절 배경 설명이며 월지가 미확정이면 생략한다. 연간 콘텐츠의 십성 주제를 그대로 복사해 원국 종합 풀이로 부르지 않는다. 연간/월운·현재 날짜·이름·난수·페이지 접속 순서는 조건에 없다.

P 60종 설명은 모두 독립 작성한다. 같은 D와 C가 같아 분야 문구가 같아도 P와 지장간·기둥별 근거는 달라질 수 있다. 차이를 만들려고 없는 특징을 추가하지 않는다. 각 설명은 ‘이 특징을 어떤 생활 관점으로 읽는지’로 작성하고 진단·예언·직업 적합성 판정으로 쓰지 않는다.

## 5. 콘텐츠 규격과 선택 우선순위

원국 상세 콘텐츠 버전은 `1.0.0`에서 시작한다. 최소 작성량은 일간 상세 10개, 일주 60개, 십성 주제 10개, 계절 4개, 월지 사실 설명 12개, D×분야 기본 50개, C×분야 맥락 50개다. 지장간 표·용어 정의는 계산/공통 자료이며 개인별 독립 문구 수로 부풀리지 않는다. D×C×S 전체 조합마다 별도 원고가 있다고 주장하지 않는다.

각 문구는 `id`, `requires`, `title`, `summary`, `paragraphs`, `question`, `action`, `version`을 가진다. 기본·일간·일주 문구는 상세 2문단 이상, 맥락·계절 보조 문구는 1문단으로 작성한다. 맥락·계절 문구의 `action`은 null로 두어 기본 행동과 별도 지시가 충돌하지 않게 한다.

ID 예: `natal.dayMaster.癸`, `natal.dayPillar.癸未`, `natal.tenGod.정관`, `natal.season.winter`, `natal.monthBranch.亥`, `natal.area.workResources.癸`, `natal.context.workResources.정관`.

선택 순서는 입력 구조 검증 → 확정 D/P 확인 → 사용 가능한 특징 생성 → 필수 조건 확인 → 정확한 키 조회 → 기본+맥락+계절 조합 → ID 중복 제거 → 근거·누락 상태 반환이다. 동일 조건 키를 중복 등록하면 개발 검증 실패로 처리한다. 목록 순서는 연·월·일·시, 십성 설명 순서는 비견·겁재·식신·상관·편재·정재·편관·정관·편인·정인으로 고정한다. 횟수로 서열을 정하지 않는다.

기본 문구 누락 시 해당 영역 전체를 미제공 처리한다. 맥락이나 계절 문구 누락은 그 보조 설명만 제외하고 부분 제공을 알린다. 다른 D/P/C/S의 문구나 공통 길흉 문구로 대체하지 않는다. 동일 ID의 주제는 1회 출력하고 모든 관련 위치를 연결한다. 동일 P/D/C 반복과 말투의 유사성은 허용하되 분야 간 상세 문단의 무의미한 복제를 검수한다.

## 6. 부분 결과·오류·근거

- 입력 없음: 두 순수 모듈 모두 null. 개인별 상세를 만들지 않고 공통 용어만 표시한다.
- 잘못된 구조·기둥 코드·표면 집계 불일치: `RangeError`. 화면은 계산 실패 안내와 정보 수정 경로를 제공한다.
- D 또는 P 없음: `unavailable-day-master` / `unavailable-day-pillar`. 상세 해석 전체 미제공이며 가상 일주를 만들지 않는다.
- 시간 미상: 시주·시 천간 십성·시 지장간 제외. 나머지 확정 영역은 제공하고 부분 결과를 알린다.
- 절입 경계: 기존 `uncertainty`를 그대로 전달한다. 후보 기둥은 안내에만 사용하고 해석 선택·집계에는 넣지 않는다. 월주 미확정이면 계절·월 지장간을 제외하고 C는 H로 전환한다. 연주만 미확정이면 월주 계절은 유지한다.
- 콘텐츠 누락: `unavailable-content`, 상위 `contentStatus: 'partial'`. 원국 특징이 미확정인 `unavailable-feature`와 구별한다.

결과에는 각 영역별 `status`, `reason`, `basis`, `contentIds`를 둔다. `basis`는 사용한 D/P, 실제 기둥 위치·간지, 십성 비교 천간, 지장간 표 ID/역할, C의 선택 사유, 계절과 월지를 포함한다. 근거 펼치기는 한글·한자·위치·채택 기준을 보여주며 내부 ID는 사용자 본문에 나열하지 않는다.

## 7. 모듈 책임과 데이터 계약

| 파일(신규 경로는 구현 기준) | 책임 |
| --- | --- |
| `js/saju-calculator.js` | 기존 출생 계산. 기존 public API와 결과 계약 유지 |
| `js/natal-features.js` | `calculateNatalFeatures(result)`: 검증된 결과에서 확정 특징만 파생. DOM·시계·저장·문구 의존 없음 |
| `js/natal-interpreter.js` | `interpretNatalDetails(features, catalog?)`: 조건에 맞는 원국 문구·근거 반환. DOM·시계·난수 없음 |
| `js/content/natal-tables.js` | 고정 지장간·월지 계절표와 버전·출처 |

15단계 반환 계약:

```text
version, policy, status, partial, excludedPillars, uncertainty
dayMaster, dayPillar
pillars.{year,month,day,hour}: null | {
  pillar, stemRelation:null|{kind:'self'|'ten-god', tenGod:null|string},
  hiddenStems:[{stem, role:'main'|'middle'|'residual', order, tenGod, tableId}]
}
surfaceElements:{counts,total,kind:'surface-characters'}
season:null|{key,monthBranch,monthElement,termName}
context:null|{tenGod,source:'month-stem'|'day-branch-main',pillarKey,stem}
availability: {areaKey:{status,reason,partial,requiredFeatures}}
```

16단계 반환은 `version`, `featureVersion`, `status`, `contentStatus`, `note`, `sections`, `contentIds`를 포함한다. `sections`는 위 화면 순서의 `{key,status,reason,title,summary,blocks,basis,contentIds}` 배열이며, `blocks`에 출처 문구 ID와 역할(`base/context/season`)을 보존한다. 반환값은 복사본이며 원본 계산·카탈로그를 변경하지 않는다. 저장은 기존 출생 프로필 키만 재사용한다. 새 출생 정보나 개인정보를 URL·서버·localStorage에 추가하지 않는다. 상세 펼치기 상태는 현재 페이지 메모리에서만 유지한다.

## 9. 15단계 구현 반영 (2026-10-19)

`js/natal-features.js`와 `js/content/natal-tables.js`를 구현했다. 신규 12개·전체 75개 검사를 통과했다. [특징 계산 검증 기록](./NATAL_FEATURES_VALIDATION.md)에 계약·실행 결과·한계를 기록했다. 콘텐츠·해석 선택·화면 연결은 16~18단계다.

구현 계약에서 `dayPillar`는 원래 기둥 설명 객체, `season.monthBranch`는 한글/한자/오행 객체, `hiddenStems.order`는 1부터 시작한다. `policy`에 표 버전/ID를 포함하고 `availability`에 영역별 partial을 추가했다. 명시적인 일간 미확정은 `features.dayMaster=null`로 전달하며 이때 `stemRelation`과 지장간 십성은 null이다. 일주 자체가 없으면 `unavailable-day-pillar`를 우선한다. 독립적인 표면/계절 사실은 남기되 일간이 필요한 해석은 제공하지 않는다. 일간 필드 누락이나 다른 값은 손상 오류로 거부한다.

## 10. 16단계 구현 반영 (2026-10-19)

`js/natal-interpreter.js`와 원국 상세 콘텐츠 196개 ID를 연결했다. 일간 10개는 기존 설명을 sourceRefs/sourceVersion으로 추적해 재사용했다. 신규 13개·전체 88개 검사를 통과했다. [콘텐츠 검수 기록](./NATAL_CONTENT_VALIDATION.md)과 [대표 출력 4건](./NATAL_CONTENT_SAMPLES.md)을 참고한다.

확정 특징은 반환 `facts`로 복사하고 section별로 `basis`·선택된 `blocks`·`contentIds`·`missingContentIds`를 남긴다. 기둥별 사실·표면 오행은 생성 문구 수에 넣지 않는다. 계절 배경은 독립 영역에서 한 번 표시한다. 원국 요약은 첫 section으로, 나머지 4개 분야는 뒤에서 출력한다. `contentStatus='complete'`는 사용 가능한 특징에 필요한 원고의 충족 여부다. 사주 일부가 미확정이어도 원고가 모두 있으면 complete이고 `partial=true`와 미제공 feature 영역을 따로 유지한다. 기본/보조 누락은 각각 unavailable-content/partial-content로 구분한다. 화면은 아직 변경하지 않았으며 17단계에서 연결한다.

## 11. 17단계 화면 연결 반영 (2026-10-19)

`saju.html`·`js/saju.js`에 `js/natal-view.js`를 연결했다. 개인별 상세 5개 그룹과 영역 앵커·본문/근거 펼치기·기둥별 지장간 목록·예외 안내를 제공한다. 기존 짧은 개인별 2개 카드는 상세로 옮기고 공통 용어 4개는 마지막 펼치기로 구분했다. 원국과 선택 기간의 운세를 구분하고 기존 연간/월운 링크를 유지한다. 전체 88개 모듈 검사와 기존/연간 월운/원국 Chrome 검사를 통과했다. [화면 검수 기록](./NATAL_UI_VALIDATION.md)을 참고한다. 종합 검증은 18단계다.


## 18단계 종합 검증 반영 (2026-10-19)

전체 94개 검사와 Chrome 3개 스크립트가 통과했다. 독립 참고 지장간 12지지·28항목 구성 일치와 나열 순서 차이 5건을 확인했다. 본기·중기·여기는 앱 채택 순서의 표시 규약이며 사령·세력 비율이 아니다. 십성 외부 명시 사례 14건과 별도 규칙표 100관계, 육십갑자 콘텐츠 60종·전통 절기 계절 구분도 확인했다. 외부 실제 날짜 전수 대조와 구분한다.
