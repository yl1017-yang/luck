# 사주 계산 후보 검증

검증일: 2026-10-15. 사용자 요청에 따라 무료 후보를 실제 배포 파일로 비교했다. 이 작업은 **후보 평가와 보정 방식의 검증**이다. 사이트의 고정 예시를 실제 사주로 바꾸는 작업은 하지 않았다.

후속 연결 완료(2026-10-15): 아래 후보 평가 이후 `js/saju-calculator.js`와 브라우저 ESM 엔진을 추가해 공통 입력·저장 복원에 연결했다. 사주팔자 화면은 실제 계산 결과를 표시한다. 후보 평가 당시의 ‘화면 미연결’ 설명은 당시 상태의 기록이다. 추가 과거 자료 대조는 계속 남아 있다.

## 결론

**한국 음력 변환은 기존 korean-lunar-calendar 0.4.0을 유지하고, 절기 계산 후보로 lunar-javascript 1.7.7 + UTC+9·자정 기준 보정 계층을 조건부 선정한다.**

- lunar-javascript의 원본 사주 출력을 그대로 사용하지 않는다. 중국 시간대와 23시 시주 규칙을 보정해야 한다.
- @fullstackfamily/manseryeok 1.0.8은 현재 서비스의 절입 시각 기준 연·월주 계산에 부적합하다.
- 아래 샘플·경계 테스트는 통과했지만 1900년부터 현재까지 모든 절기 시각을 독립 자료와 대조한 것은 아니다. 전체 기간에 대한 정확성 보증으로 표현하지 않는다.

원본과 LICENSE, 출처·해시는 [tests/vendor/README.md](../tests/vendor/README.md)에 보관한다. 검증용 파일은 앱에서 import하지 않는다. lunar 후보는 공개 릴리스·테스트 이력을, manseryeok 후보는 2026년 2~3월 오류 수정 이력을 확인했다. 이는 앞으로의 유지보수를 보장하지 않는다.

## 발견한 차이와 판단

### manseryeok: 절입 시각 경계 미충족

`calculateSaju`는 연·월·일주를 `getGapja(year, month, day)`로 계산한다. 월 경계도 월·일별 고정 표를 사용한다. 출생 시간은 시주에만 영향을 준다.

실행 결과 2024-02-04 00:00과 23:00 모두 연주 갑진·월주 병인을 반환했다. KASI 자료의 이날 입춘은 17:27이므로 00:00에는 이전 연·월을 유지해야 하는 서비스 기준을 만족하지 못한다. 1900년 절기 시각 조회도 지원하지 않는다. 따라서 이 버전을 수정 없이 채택하지 않는다.

### lunar-javascript: 시간대·시주 보정 필요

1. 절기 시각은 UTC+8 벽시각이다. 절기표에는 1시간을 더해 고정 UTC+9로 변환한다. 연·월주 비교 입력은 반대로 한국 시각에서 1시간을 빼 동일한 순간의 UTC+8 성분으로 전달한다.
2. 일주·시지에까지 1시간을 빼면 한국 자정과 시지 경계가 틀어진다. 일주는 원래 한국 날짜의 `getDayInGanZhiExact2`를 사용한다.
3. `setSect(2)`는 일주를 자정 기준으로 만들지만 시주의 천간은 여전히 23시 다음 날 기준을 사용한다. 시주는 한국 일간과 시지로 재계산해야 한다.
4. 한국 음력 입력을 이 엔진에 직접 전달하지 않는다. 기존 한국 음력 변환기로 양력 환산 후 전달한다.
5. 시간 미상일 때 임의의 출생 시간을 확정하지 않는다. 하루 시작·끝의 연·월주를 비교해 절입 당일 불확실한 값을 null과 상태 정보로 반환하고 시주는 제외한다. 이 시각들은 불확실성 판정용이지 가상의 출생 시간 저장값이 아니다.

위 보정은 [검증용 어댑터](../tests/helpers/saju-candidate.mjs)에만 구현했다. 앱용 모듈로 옮길 때 입력 검증·오류 처리·정밀도 안내를 추가해야 한다.

## 다음 구현 때 필요한 사항

- 검증용 보정 계층을 브라우저용 사주 계산 모듈로 분리하고, 입력 검증 및 반환 구조를 정리한다.
- 경계에 매우 가까운 출생 시각은 분 단위 입력·참고표·엔진 오차를 고려해 불확실성을 안내한다. 특히 이번 비교에서 절입 시각 ±1분 안의 결과까지 독립적으로 확정했다고 표현하지 않는다.
- 전체 1900년 지원을 강하게 주장하기 전에는 과거 절기 자료와 추가 교차 비교한다. 현재는 실행 범위와 월별 일주 표본 확인 수준이다.
- 후보 선정·표본 경계 검증은 실행순서 3단계 완료로 처리하고, 과거 절기 추가 대조는 별도 항목으로 관리한다.

## 앱 연결 결과 구조

`calculateSaju(profile)`는 입력 오류 시 RangeError를 발생시키고, 성공 시 다음 데이터를 반환한다.

- profile: 이름·출생 날짜·달력·윤달·출생 시간(시간 미상 null)
- dates: 한국 음력 변환기로 얻은 양력·음력 날짜
- pillars: year/month/day/hour별 한자·한글과 천간·지지의 오행. 미확정 기둥은 null
- features: 일간, 확정된 천간·지지의 단순 오행 개수, 전체 개수, 일부 결과 여부
- uncertainty: 시간 미상 절입 당일 또는 절입 ±60초의 이유·미확정 기둥·양쪽 후보
- policy, engine: UTC+9·자정·무보정 정책과 엔진 식별자

공통 입력은 계산 성공 후 현재 페이지 결과를 갱신하고 출생 정보만 sessionStorage에 저장한다. 다른 페이지에서는 저장 정보를 재검증·재계산한다. 저장 차단 시에도 현재 화면은 계산되며, 입력 오류·계산 오류에는 저장하거나 기존 결과를 덮어쓰지 않는다.

실제 모듈 테스트는 `node --experimental-default-type=module tests/saju-calculator.test.mjs`로 실행한다. 브라우저용 엔진 포장 변경 전후 계산 본문 동일성, 검증용 어댑터와 40개 날짜·시간 조합의 일치, 결과 구조, 시간 미상, 경계 정밀도, 윤달·복원·오류 처리를 확인한다. 실제 브라우저 입력 조작 검수는 별도로 필요하다.
