# 운세 사이트 실행순서

이 문서는 [GUIDE.md](./GUIDE.md)의 개발 방향을 실제 작업 순서로 정리한 체크리스트다. 앞으로 아래 순서대로 진행하고, 완료한 항목만 체크한다.

## 개발 범위

- 1차: 오늘의 운세·사주팔자·내 성향
- 이후: 콘텐츠 보강과 평생운세 확장
- 구현 방식: 자체 계산 + 저장된 해석 문구
- 운영 중 외부 운세 API와 AI API 호출 없이 결과를 제공한다.

## 1. 프로젝트 상태 확인

- [x] `luck` 폴더의 기존 코드와 프로젝트 지침을 확인한다.
- [x] 사용 기술, 패키지 구성, 실행·빌드 방법을 확인한다.
- [x] 현재 구현된 기능과 추가로 필요한 기능을 정리한다.
- [x] 계산 기능, 해석 데이터, 화면을 배치할 구조를 정한다.

완료 조건: 현재 프로젝트를 실행하는 방법과 구현할 파일·기능의 위치가 정리되어 있다. 기존 코드가 없다면 기본 프로젝트 구성을 먼저 준비한다.

## 2. 입력 항목과 계산 기준 확정

- [ ] 생년월일, 양력·음력, 음력 윤달 여부, 출생 시간을 공통 입력으로 정한다.
- [ ] 출생 시간에 ‘시간 모름’ 옵션을 둔다.
- [ ] 지원할 생년월일 범위를 정한다.
- [ ] 출생지·시간대 지원 범위를 정하고 화면에 안내할 기준을 마련한다.
- [ ] 절기, 날짜 경계, 출생 시간 미상 처리 기준을 문서화한다.
- [ ] 오늘의 운세 날짜가 바뀌는 시간대와 갱신 기준을 정한다.
- [ ] 입력 정보의 저장 여부와 저장 위치를 정한다.

완료 조건: 같은 입력을 어떤 기준으로 계산하는지 명확하며, 라이브러리 선정에 필요한 요구사항이 정리되어 있다.

## 3. 만세력 라이브러리 선정·계산 검증

- [ ] 후보 라이브러리의 라이선스, 유지보수 상태, 지원 범위를 확인한다.
- [ ] 양력·음력 변환, 윤달, 절기와 시간 처리를 확인한다.
- [ ] 프로젝트에 맞는 라이브러리를 선정한다.
- [ ] 알려진 사례와 대표 입력으로 연주·월주·일주·시주를 비교한다.
- [ ] 절기 전후, 날짜 경계, 윤달, 출생 시간 미상 사례를 확인한다.
- [ ] 비교에 사용한 출처와 계산 기준, 발견한 차이를 기록한다.

완료 조건: 지원 범위 내 계산 결과를 검증했고, 차이가 있는 사례의 원인을 설명하거나 해결했다.

## 4. 공통 입력 화면과 계산 기능 구현

- [ ] 생년월일과 달력 구분 입력 화면을 구현한다.
- [ ] 음력 선택 시 윤달 입력을 처리한다.
- [ ] 출생 시간 및 ‘시간 모름’을 처리한다.
- [ ] 유효하지 않은 날짜와 지원 범위를 벗어난 입력을 안내한다.
- [ ] 입력 정보를 계산 함수에 연결한다.
- [ ] 사주팔자와 해석에 사용할 특징을 공통 결과 구조로 반환한다.

완료 조건: 입력부터 계산 결과 반환까지 연결되며, 잘못된 입력과 시간 미상도 정상적으로 처리된다.

## 5. 해석 콘텐츠와 연결 규칙 준비

- [ ] 문구를 코드와 분리해 수정 가능한 데이터로 저장한다.
- [ ] 사주팔자: 각 기둥, 일간, 오행 등 표시할 용어의 설명을 작성한다.
- [ ] 내 성향: 행동 방식, 강점, 관계 방식, 스트레스 경향, 균형을 잡는 팁을 작성한다.
- [ ] 오늘의 운세: 오늘의 흐름, 관계, 일·공부, 생활 조언, 주의점, 실천 팁을 작성한다.
- [ ] 계산된 특징과 문구를 연결하는 조건을 정의한다.
- [ ] 오늘 날짜를 반영하는 운세 선택 규칙을 정의한다.
- [ ] 문구의 우선순위와 상충하는 문구의 제외 조건을 정한다.
- [ ] 같은 입력과 같은 날짜에 같은 결과를 제공하도록 구성한다.
- [ ] 단정적인 예측, 불안을 유발하는 표현, 중대한 의사결정을 유도하는 문구를 검토한다.

완료 조건: 지원하는 입력에 필요한 기본 해석이 제공되고, 내용이 모순되거나 빈 영역으로 남지 않는다. 콘텐츠용 해석 규칙과 만세력 계산은 구분해 관리한다.

## 6. 세 메뉴 결과 화면 구현

- [ ] 사주팔자: 계산 정보와 쉬운 용어 설명을 표시한다.
- [ ] 내 성향: 강점·관계·스트레스·행동 팁을 구분해 표시한다.
- [ ] 오늘의 운세: 적용 날짜와 분야별 해석, 실천 팁을 표시한다.
- [ ] 출생 시간 미상일 때 제공할 수 있는 결과 범위를 안내한다.
- [ ] 입력을 수정하고 결과를 다시 확인할 수 있게 한다.
- [ ] 모바일에서 읽기 편한 글자 크기와 화면 구성을 적용한다.
- [ ] 재미와 자기 성찰을 위한 콘텐츠라는 안내를 제공한다.

완료 조건: 공통 입력 후 오늘의 운세·사주팔자·내 성향을 모두 확인할 수 있다.

## 7. 1차 검수와 콘텐츠 보강

- [ ] 양력·음력·윤달·시간 미상 등 주요 입력 사례를 확인한다.
- [ ] 계산 결과를 기준 사례와 다시 비교한다.
- [ ] 같은 입력의 결과 일관성과 오늘의 운세 날짜 갱신을 확인한다.
- [ ] 문구의 모순, 과도한 반복, 설명 누락을 확인한다.
- [ ] 모바일 화면, 입력 오류 안내, 결과 재조회 흐름을 확인한다.
- [ ] 프로젝트에서 요구하는 빌드·검사와 계산 핵심 로직에 필요한 검증을 수행한다.
- [ ] 결과를 실제로 읽어보고 가독성과 콘텐츠 다양성을 보강한다.

완료 조건: 세 메뉴의 기본 흐름이 동작하고, 발견된 주요 오류를 해결했다. 남은 제한사항과 검수 결과를 기록한다.

## 8. 평생운세 확장

1차 검수가 끝난 뒤 진행한다.

- [ ] 평생운세의 제공 범위를 정한다.
- [ ] 인생 전반의 경향을 설명하는 기본 콘텐츠를 준비한다.
- [ ] 시기별 흐름을 포함할 경우 대운·세운 계산 기준과 추가 입력 필요 여부를 확인한다.
- [ ] 시기별 계산을 검증하고 해석 콘텐츠를 연결한다.
- [ ] 결과 화면을 추가하고 문구의 일관성과 예외 상황을 검수한다.

완료 조건: 정한 범위의 평생운세가 제공되며, 계산 기준과 해석의 제한사항이 정리되어 있다.

## 진행 기록

작업을 마칠 때 아래 표에 변경 내용과 검증 결과를 기록하고, 해당 체크박스를 갱신한다. 진행 중 새로운 결정이 생기면 이 문서와 GUIDE.md에 함께 반영한다.

### 현재 구현 상태와 다음 작업

공통 UI 클래스 정리 완료: 버튼 색상·아이콘·전체 너비, 배지, 입력창, 카드 배경, 대시보드 그리드를 공통화하고 세 HTML과 동적 배지 출력에 반영했다.

화면을 먼저 확인할 수 있도록 고정 예시 데이터로 대시보드를 구현했다. 기본 구성은 메뉴별 HTML, 공통 CSS, 공통·메뉴별 JavaScript와 예시 데이터이며 외부 패키지 설치나 빌드는 없다. 로컬 실행 방법은 README.md에 기록했다.

출생 정보 입력·수정과 메뉴 전환은 구현했지만 실제 사주 계산은 하지 않는다. 따라서 위 계산 검증 및 개인별 해석 관련 체크리스트는 완료로 표시하지 않는다. 출생 정보는 같은 탭에서 임시 유지되고 실천 체크는 페이지 이동·새로고침 시 초기화된다.

다음 작업은 2단계의 계산 기준과 지원 범위 확정, 3단계의 만세력 라이브러리 선정·검증이다. 현재 날짜 입력은 브라우저의 양력 날짜 입력을 사용하므로, 음력의 실제 유효성과 음력에만 존재하는 날짜를 처리할 입력 방식은 라이브러리 연결 시 보완해야 한다.

메뉴별 HTML 분리 완료: `index.html`, `saju.html`, `personality.html`. 공통 입력은 `js/common.js`, 메뉴별 출력은 `js/today.js`, `js/saju.js`, `js/personality.js`로 분리했다. 출생 정보는 sessionStorage로 같은 탭에서 유지되고 실천 체크는 페이지 이동·새로고침 시 초기화된다.
